# Rust migration results

The production application is now a single native Rust executable. CAST decoding, merge semantics, workspace state, settings, localization, two-task scheduling, preview sampling and the eframe/egui/wgpu interface all run in-process. The former WPF/C# application and the NDJSON worker remain only as source-level compatibility evidence and protocol tests; neither is included in a release.

## Runtime architecture

- `model-merger-gui` owns the native windows, five-language interface, file/folder dialogs and independent preview viewports.
- `model-merger-app-core` owns collapsible groups, 15-slot validation, remembered paths, atomic JSON settings and the scheduler with a hard limit of two active merges.
- `model-merger-engine` owns merge planning, root selection, cancellation, safe temporary output, verification and preview sampling.
- `cast-codec` performs bounds-checked CAST reads and writes, including 32-bit face-index properties.
- The release has no worker subprocess, C# fallback, .NET dependency or Rust runtime dependency.

Preview geometry is capped at 75,000 displayed triangles. Sampling affects only the interactive view; merging always uses the complete model. Loading is cancellable, and each preview window offers mouse, button and keyboard controls.

## Compatibility gates

The migration corpus was generated by the C# writer and covers connected skeletons, materials, UVs, colors, weights, faces and blend shapes. Tests exercise 2, 8 and 15-part merges, automatic and manual roots, overwrite protection, cancellation cleanup, malformed and truncated CAST data, 32-bit face indices, atomic settings recovery, all five language catalogs, accessibility trees and scheduler output-path claims.

On the local Windows x64 Release benchmark (20,000 triangles per part), semantic summaries from the C# and Rust outputs matched:

| Parts | Former C# median | Rust engine median | Improvement |
| ---: | ---: | ---: | ---: |
| 2 | 349 ms | 35 ms | 89.9% |
| 8 | 1,384 ms | 81 ms | 94.1% |
| 15 | 2,472 ms | 182 ms | 92.6% |

For a 20,000-triangle preview, C# and Rust geometry hashes matched and the warm median was 68.2 ms for C# versus 43.5 ms for Rust. A 50,000-triangle, 150,000-vertex model that the legacy loader cannot read completed in a warm Rust median of 81.1 ms. These figures are development-machine comparisons, not universal performance promises; the native GUI removes the worker-process startup boundary used while collecting the Rust baselines.

## Release profile

The Windows x64 release uses optimization level 3, thin LTO, one code-generation unit and stripped symbols. On the acceptance build, `CastModelMerger.exe` was 21,259,776 bytes. The renderer increases idle working set compared with WPF (approximately 239 MiB versus 135 MiB on the acceptance machine), but the package is self-contained, starts without .NET and avoids duplicate GUI/worker processes.

## Source layout

```text
rust/crates/cast-codec            Bounds-checked CAST binary codec
rust/crates/model-merger-engine   Merge, validation, safe output and preview sampling
rust/crates/model-merger-app-core Workspace state, settings, localization and scheduler
rust/crates/model-merger-gui      Native eframe/egui/wgpu desktop application
rust/crates/model-merger-worker   Migration compatibility protocol tests only
```
